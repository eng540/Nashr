## Findings

### Artifact
The boundary is small and provider-neutral. It contains output identity, source knowledge identity, kind, content, editorial status and timestamps. It has no Telegram dependency.

### Production
Production now exposes an Artifact representation at the application boundary while retaining the existing Post persistence contract.

### Review
Review remains intentionally Post-centric. It mutates editorial state and protects the current product behavior. Moving it now would mix mutable editorial ownership with the first Artifact extraction.

### Publication
Publication remains Post-centric in persistence and application. It is the safest next consumer because Publication already represents the durable output ledger immediately before external distribution.

### Scheduling
Scheduling remains Post-centric and must preserve the final APPROVED check immediately before publication, plus PUBLISHED→SKIPPED and idempotency.
