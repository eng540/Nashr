# Nashr — سجل الوظائف والتدفقات

**نقطة الأساس المفحوصة:** `main` عند `f2122d4ff75b1228d910f7ad6dd4c0461c00c774` (2026-10-12).  
**الغرض:** مرجع حي لمنع فقدان الوظائف عند إعادة تنظيم الواجهات.  
**الحالة:** جرد أولي مبني على ملفات الواجهة وعقود API والخلفية المذكورة أدناه؛ لا يعني أن كل وظيفة اختُبرت بصريًا أو على بيئة تشغيل حية.

## 1. دلالات الحالة

- **متحققة بالكود:** التنفيذ أو عقد API ظاهر ومحدد في الملفات المشار إليها؛ ليس إثباتًا للتشغيل الحي.
- **جزئية:** المسار موجود لكن تجربة المستخدم أو تغطية القبول لا تغطي كل الحالات.
- **معطلة:** دليل على أن الوظيفة لا تعمل في الحالة الحالية.
- **غير متحقق منها:** لم يتوفر دليل كافٍ للحكم على سلوكها الكامل.

الحالة التنفيذية منفصلة عن حالة التشغيل: «منفذة» تعني تغييرًا برمجيًا، أما «متحقق منها» فتتطلب اختبارًا مسجلاً.

## 3. تدفقات العمل من البداية للنهاية

### FLOW-01 — إعداد مطالبة إنتاج
1. المدخلات: منتج نشط، مصدر، نطاق `SOURCE/TOPIC/SELECTION`، وهوية اختيارية.
2. مصدر البيانات: المنتجات والهويات والوصفات، `GET /sources`، `GET /sources/{id}/book-map`.
3. الشروط: منتج مختار؛ مصدر صالح؛ محور تابع للمصدر عند `TOPIC`؛ مادة واحدة على الأقل عند `SELECTION`؛ خريطة كتاب محملة بنجاح وعدد النطاق أكبر من صفر.
4. المخرج: ملخص واضح مطابق للطلب ثم `POST /production-jobs` بمفتاح idempotency.
5. الفشل/التعافي: تحميل/خطأ/فراغ واضح؛ لا يبدأ الطلب؛ عند غموض الرد يحتفظ بالمفتاح والحمولة نفسها.

### FLOW-02 — متابعة مهمة
1. المدخل: `job_id`.
2. API: `GET /production-jobs/{id}` و`GET /production-jobs/{id}/items`.
3. الحالات: job QUEUED/RUNNING/COMPLETED/FAILED؛ item PENDING/RUNNING/COMPLETED/FAILED.
4. المخرج: التقدم والعدّادات والعناصر والأخطاء والمخرجات.
5. التعافي: `WAIT` أثناء التنفيذ؛ `RETRY_FAILED_ITEMS` فقط عندما يسمح API؛ `INSPECT_FAILURE` عند الفشل أو التسوية؛ `REVIEW_DRAFTS` عند اكتمال المهمة.
6. لا إلغاء/إيقاف مؤقت مستقل في عقد المهمة الذي فُحص.

### FLOW-03 — مراجعة منشورات
1. المصدر: بنك المنشورات المصفّى والمقسّم إلى صفحات.
2. الإجراءات: فتح منشور، تحرير، حفظ، اعتماد، رفض، اعتماد جماعي.
3. المخرج: تحديث Post وحالته.
4. الشرط قبل النشر: حالة معتمدة وأهلية حسب API؛ لا يكفي أن يكون المنشور محددًا.

### FLOW-04 — مراجعة Artifact غير المنشوري
1. المصدر: `GET /api/artifacts?review_status=...`.
2. الحالات: DRAFT/APPROVED/REJECTED.
3. الوسائط: صورة/فيديو/صوت من رابط مؤقت عند وجود `storage_uri`.
4. الإجراءات: تحرير محتوى إن كان نصيًا، حفظ، اعتماد، رفض.
5. الفشل: عرض تحميل/خطأ/فراغ ومعاينة فاشلة؛ لا تعتبر رابط الوسيط متوفرًا دون استجابة فعلية.

### FLOW-05 — خطة النشر
1. المصدر: المحتوى المعتمد والمؤهل.
2. تحديد: أفراد أو عناصر الصفحة؛ توضيح أن تحديد الصفحة لا يعني كل نتائج المرشح.
3. إنشاء: اسم، منطقة زمنية، وقت بداية، فاصل بالدقائق.
4. مراجعة: تفاصيل الخطة والعناصر وأوقاتها.
5. تشغيل: تفعيل/إيقاف مؤقت/إلغاء وإعادة محاولة حسب الحالة.
6. الحماية في هذا المشروع: لا تفعيل لخطة اختبار ولا إرسال Telegram ولا نشر خارجي حقيقي.
